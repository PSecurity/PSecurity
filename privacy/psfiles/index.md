<section class="ps-workspace ps-v67-policy-surface" aria-labelledby="psfiles-data-title">
  <div class="ps-v63-section-head">
    <div>
      <p class="ps-section-label">DATA HANDLED</p>
      <h2 id="psfiles-data-title" class="ps-workspace-title">Information processed by PS.Files</h2>
      <p class="ps-workspace-subtitle">PS.Files may access or process the following information when the user grants permission or uses a related feature.</p>
    </div>
  </div>
  <div class="ps-v67-policy-grid">
    <article class="ps-v67-policy-row"><span>01</span><strong>Local files and folders</strong><small>Files, folders, names, paths, sizes, dates and file metadata required for browsing, selection, copy, move, rename, delete, archive, restore and preview actions.</small></article>
    <article class="ps-v67-policy-row"><span>02</span><strong>Storage analysis data</strong><small>Local results generated to help the user understand storage usage, duplicates, large files or file categories on the device.</small></article>
    <article class="ps-v67-policy-row"><span>03</span><strong>Hashes and reports</strong><small>Hash values, comparison results and operation reports generated locally when the user runs integrity, archive or operation-console features.</small></article>
    <article class="ps-v67-policy-row"><span>04</span><strong>Installed apps information</strong><small>When the user uses installed-app export or inspection features, PS.Files may read installed package/app information available through Android APIs.</small></article>
    <article class="ps-v67-policy-row"><span>05</span><strong>Protected local items</strong><small>If the user uses Secure Space or protected access features, selected items and indexes are stored in app-private protected storage according to the implemented encryption flow.</small></article>
    <article class="ps-v67-policy-row"><span>06</span><strong>Support communication</strong><small>If the user contacts PeekSecurity by e-mail, the message content, e-mail address and device/testing details provided by the user may be used to respond and investigate the issue.</small></article>
  </div>
</section>

<section class="ps-workspace ps-v67-policy-surface" aria-labelledby="psfiles-security-title">
  <div class="ps-v63-section-head">
    <div>
      <p class="ps-section-label">SECURITY</p>
      <h2 id="psfiles-security-title" class="ps-workspace-title">Security, retention and deletion</h2>
    </div>
  </div>
  <div class="ps-v67-policy-ledger">
    <article><span>Protection</span><strong>Secure Space and protected access</strong><small>Protected items are stored locally in the app-private area using the security model implemented by PS.Files. Access may use PIN, password or biometrics depending on the build and user configuration.</small></article>
    <article><span>Clean Share</span><strong>Metadata-reduced copies</strong><small>Clean Share features generate cleaned copies for user-initiated sharing. The original user file remains under user control unless the user deletes or moves it.</small></article>
    <article><span>Retention</span><strong>Local retention follows user actions</strong><small>Local files, secure items, reports, trash records and app-private data remain on the device until deleted by the user, cleared by the app, removed by Android behavior, or removed by uninstalling the app.</small></article>
    <article><span>Deletion</span><strong>User control</strong><small>The user can delete files, clear local reports/trash records where available, remove protected items and uninstall the app to remove app-private data subject to Android system behavior.</small></article>
  </div>
</section>
